Gramatyka — 4 tokeny, każdy inny typ
Anatomia linii OQL
SET   pump-main   5.0   l/min
 │         │          │       │
 │         │          │       └─ UNIT  opcjonalny, może mieć /
 │         │          └───────── VALUE liczba (int lub float, może być ujemna)
 │         └──────────────────── TARGET identyfikator (litery, cyfry, -)
 └────────────────────────────── CMD   zawsze UPPERCASE

MIN   AI02        6.0   bar      ← ta sama struktura co SET
WAIT  3s                            ← VALUE+UNIT sklejone (bez spacji)
WAIT  3000                          ← gołe ms (domyślna jednostka)
READ  AI02                          ← tylko TARGET
SAVE  cisnienie_sc                  ← tylko TARGET
CHECK 6.0 <= AI02 <= 8.0 bar      ← specjalna składnia
Reguły tokenizacji — każda komenda zna swoją strukturę
Znane struktury argumentów
SET    → TARGET VALUE [UNIT]
MIN    → TARGET VALUE UNIT
MAX    → TARGET VALUE UNIT
WAIT   → DURATION        (3s|3000ms|3000)
READ   → TARGET
SAVE   → TARGET
SAMPLE → TARGET START|STOP [INTERVAL]
CHECK  → MIN <= TARGET <= MAX UNIT
ERROR  → "message string"
GOAL   → name:   (blok)
CONFIG → name:   (blok)
Reguły wartości
# VALUE: liczba (int lub float)
0    5.0    -10.5    145

# UNIT: jeden token po VALUE
bar   mbar   l/min   °C   %RH

# DURATION: VALUE sklejone z UNIT
3s  500ms  60s  3000 (=ms)

# TARGET: identyfikator
pump-main  AI02  valve-nc
cisnienie_sc  test-result
